# Spec and plan: Zabbix 7.0 LTS series

Status: proposed. Target: Zabbix **7.0.32** (newest 7.0 release at time of writing).

## 1. Goal

Ship the Windows proxy MSI for the Zabbix 7.0 LTS series, so sites whose
Zabbix server is 7.0 can run a matching proxy (the proxy major version must
equal the server's). 7.0 becomes a supported series next to 8.0 (`main`) and
7.4.

### In scope
- A `7.0` branch with its own `UPSTREAM_VERSION`, overlay and patches.
- An MSI `zabbix_proxy-7.0.x-x64.msi` with the same features as the 7.4/8.0
  builds (active/passive, SQLite, ICMP, SNMP and traps, SSH/ODBC/LDAP, JS
  preprocessing, runtime control), the same installer behaviour and the same CI
  test matrix (Windows Server 2022 and 2025).
- README, operator guide and CI updated for the new series.

### Out of scope
- Server, frontend or agent builds. Code signing. IPMI. Changing upstream
  behaviour beyond what Windows requires. Backporting 8.0-only fixes unless
  7.0 shows the same defect.

## 2. Facts established

- The project is **C** (C11 for 8.0). The overlay is 7 `.c` and 4 `.h` files,
  and `patches/` change upstream C sources. No C++ is involved.
- `main` is 8.0.0. The 7.4 port exists only in history (last 7.4 state:
  commit `99d1dd3`, `UPSTREAM_VERSION` 7.4.16). No `7.4` branch exists on the
  remote yet, although the README and CI refer to one.
- 7.0 forks one process per worker, as 7.4 does. 8.0's supervisor model is
  not present, so the 8.0 patches are the wrong starting point.
- 7.0.32 contains no `stdatomic`/`_Atomic` use, so `/std:c11` and
  `/experimental:c11atomics` are not needed for it.
- SQLite code in 7.0 is in `src/libs/zbxdb/db.c` and `zbxdbhigh/db.c`. The
  7.4 files `zbxdb/dbconn.c` and `dbconn_compat.c` do not exist.
- `deb` package supplied by the user is only apt repo configuration; it plays
  no part in the build.

## 3. Design decisions

1. **Base on the 7.4 patch set**, branched from `99d1dd3`, not from `main`.
   7.0 is architecturally the 7.4 process model; 8.0's supervisor changes
   would be dead weight and a source of false conflicts.
2. **Same structure**: nine themed patches, same `series` order, same overlay
   layout. A reviewer can diff the 7.0 and 7.4 patch sets to see exactly what
   differs per series.
3. **Drop C11 flags** unless the build proves they are needed. Keep the
   `CFLAGS` split that keeps `/std:c11` away from C++ sources only if retained.
4. **No behaviour changes to the port** beyond adapting to 7.0 code. Anything
   that looks like a bug in the 7.4/8.0 port is raised separately.
5. **Series branch model as documented**: branch `7.0`, releases tagged
   `v7.0.32-<n>` on that branch, never marked "latest".

## 5. Acceptance criteria
1. `scripts/prepare.sh` on branch `7.0` yields a tree at 7.0.32 with zero
   rejects and no conflict markers.
2. CI is green on every job for Server 2022 and 2025.
3. The MSI installs, runs as a service, collects data from a stand-in 7.0
   server, and upgrades in place keeping an edited `zabbix_proxy.conf`.
4. The GitHub release for `v7.0.32-1` contains the MSI and `SHA256SUMS`, and is
   not marked latest.
5. README lists 7.0 with correct branch and release links.

## 6. Risks

| Risk | Impact | Mitigation |
|---|---|---|
| 7.0 differs from 7.4 in IPC/async poller internals more than the 4 conflicts suggest | Runtime hangs or crashes that compile fine | Rely on the ASAN selftest and pinger load check; add targeted checks if they fail |
| SQLite WAL change relocates to a different init path | Syncer threads block each other | Reproduce with the load check; compare buffer behaviour with 7.4 |
| Hand-written nmake object lists drift from 7.0's sources | Link errors, or silently missing features | Diff source dirs against `Makefile_proxy`; use the new-sources report |
| No Windows build available in this environment | Slow feedback loop | Batch fixes per CI run; keep commits per patch |
| 7.0 EOL arrives soon | Short support window | State it in the README; keep the port cheap by mirroring 7.4 |
| Upstream 7.0.x point releases break patches | Maintenance burden | Weekly upstream-watch already covers every series branch |
